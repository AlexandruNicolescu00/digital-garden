# Modulo 9: Forensics delle Macchine Virtuali e Acquisizioni Live

## Introduzione
Questo modulo esplora le procedure avanzate per l'analisi forense delle macchine virtuali (VM), le acquisizioni live (su sistemi accesi) e le acquisizioni remote. Con la diffusione della virtualizzazione e del cloud computing, gli investigatori devono comprendere come operano gli hypervisor, come rilevare la presenza di VM su un sistema host e come acquisire dati volatili (RAM) che andrebbero persi con uno spegnimento tradizionale.

---

## 1. Panoramica sulla Forensics delle Macchine Virtuali

Le macchine virtuali (VM) permettono di eseguire sistemi operativi (OS) alternativi all'interno di un OS esistente o direttamente sull'hardware. Sono ampiamente utilizzate per ridurre i costi hardware, gestire reti virtuali e testare software.

### Tipi di Hypervisor
Il software che gestisce le VM è chiamato **hypervisor**. Ne esistono due categorie principali:

* **Hypervisor di Tipo 1 (Bare Metal):**
    * Vengono installati direttamente sull'hardware fisico senza richiedere un sistema operativo sottostante.
    * Sono comuni in ambienti enterprise e data center (es. cluster di server).
    * Possono ospitare migliaia di VM.
    * Esempi: **VMware vSphere**, **Microsoft Hyper-V Server**, **Citrix Hypervisor**, **IBM PowerVM**.
* **Hypervisor di Tipo 2 (Hosted):**
    * Eseguiti come applicazione sopra un sistema operativo esistente (Windows, Linux, macOS).
    * Sono quelli che si trovano più frequentemente sui computer dei sospettati.
    * Esempi: **VMware Workstation Player**, **Oracle VirtualBox**, **Parallels Desktop**.

### File Associati alle Macchine Virtuali
Ogni software di virtualizzazione utilizza estensioni file specifiche che un investigatore deve saper riconoscere:

**VMware:**
* `.vmdk`: Contiene il disco rigido virtuale (i dati effettivi).
* `.vmx`: File di configurazione.
* `.nvram`: Stato del BIOS della VM.
* `.vmem`: File di paging della VM (funge da RAM).
* `.log`: Log delle attività (accensione, spegnimento, ecc.).

**VirtualBox:**
* `.vdi`: File immagine del disco virtuale.
* `.vbox`: Impostazioni dei dischi virtuali.
* `.ova` / `.ovf`: File preconfigurati per creare o esportare VM (Open Virtualization Format).

### Rilevamento delle VM su un Host
Gli investigatori devono cercare indizi che suggeriscano l'uso di VM:
* **Registro di sistema:** Cercare chiavi associate a VMware o VirtualBox.
* **Schede di rete virtuali:** Controllare le connessioni di rete (tramite `ipconfig` o impostazioni) per adattatori virtuali (es. "VMware Network Adapter", "VirtualBox Host-Only Network").
* **Cartelle utente:** Cercare nelle cartelle Documenti o Utente directory predefinite come "VirtualBox VMs".
* **Dispositivi USB:** Controllare se ci sono VM annidate o eseguite da drive esterni.

## 2. Acquisizione e Analisi delle VM

L'indagine su una VM segue passaggi specifici per garantire l'integrità delle prove:
1.  **Acquisire l'immagine dell'host:** Copiare l'intero disco fisico della macchina ospitante.
2.  **Esportare i file della VM:** Estrarre file come `.vmdk`, `.vdi`, log e snapshot.
3.  **Hashing:** Calcolare l'hash dei file associati alla VM.
4.  **Analisi:**
    * **Metodo Statico:** Montare il file immagine della VM come un drive esterno (usando strumenti come FTK Imager o OSForensics) e analizzarlo come un normale disco.
    * **Metodo Live (Booting):** Avviare la VM da una copia forense. Questo altera le prove (modifica lo stato), ma è utile per rilevare malware, vedere il comportamento del sistema o bypassare alcune protezioni. È essenziale lavorare su una copia e documentare ogni passaggio.

### Importanza degli Snapshot
Uno **snapshot** registra lo stato di una VM in un momento specifico. Non è un backup completo, ma una registrazione delle modifiche. Le acquisizioni live sono spesso necessarie per includere gli snapshot, poiché un'immagine statica del file disco originale potrebbe non contenere le modifiche più recenti salvate negli snapshot.

## 3. Acquisizioni Live (Live Acquisitions)

Un'acquisizione live cattura i dati mentre il computer è ancora acceso.

### Quando è necessaria
* Il sistema ha la crittografia del disco intero (WDE) attiva e lo spegnimento renderebbe i dati inaccessibili.
* Si sospetta la presenza di dati cruciali nella RAM (password, processi attivi, chiavi di decrittazione).
* È in corso un attacco di rete o un'intrusione attiva.
* Il sistema non può essere spento per motivi operativi (server mission-critical).

### Ordine di Volatilità (Order of Volatility - OOV)
Quando si acquisiscono dati da un sistema vivo, bisogna procedere dai dati più volatili (che svaniscono prima) a quelli meno volatili:
1.  **RAM:** Estremamente volatile, svanisce in millisecondi allo spegnimento.
2.  **Processi in esecuzione e connessioni di rete.**
3.  **Dati su disco rigido.**
4.  **Supporti di archiviazione remoti o offline.**

### Procedura Generale
1.  Utilizzare un dispositivo USB o CD forense avviabile con strumenti precaricati per minimizzare l'impatto sul sistema sospetto.
2.  Documentare ogni azione (poiché l'acquisizione live modifica inevitabilmente lo stato della RAM e dei processi).
3.  Salvare i dati acquisiti su un drive esterno o di rete, mai sul drive del sospettato.
4.  Copiare la memoria fisica (RAM) usando strumenti come **FTK Imager**, **Belkasoft RamCapturer**, **Mandiant Memoryze** o strumenti Linux come **LiME**.

### Acquisizioni Live in Linux
A causa della varietà di kernel e distribuzioni, le acquisizioni Linux sono complesse. Strumenti comuni includono:
* **LiME (Linux Memory Extractor):** Modulo del kernel per acquisire la RAM.
* **Volatility:** Framework per l'analisi della memoria.
L'ordine di priorità rimane: RAM -> Log -> Traffico di rete -> Disco.

### Acquisizioni Selettive
In alcuni casi (es. e-discovery o mandati limitati), non si acquisisce l'intero disco ma solo file specifici. Questo si può fare localmente o via rete, ma non permette l'uso di write-blocker hardware poiché il sistema deve restare attivo.

## 4. Acquisizioni Remote

L'acquisizione remota avviene tramite rete, spesso in contesti aziendali per indagini interne (es. spionaggio industriale) o e-discovery.

### Strumenti RAFT (Remote Acquisition Forensics Tools)
Questi strumenti permettono di monitorare, accedere e creare immagini di sistemi lontani fisicamente.
* **Belkasoft R:** Usa un'architettura Server (computer dell'investigatore) ed Endpoint (computer target). Si installa un "agente" sul target per eseguire l'acquisizione (disco, RAM, dispositivi mobili).
* **F-Response:** Permette di montare dischi remoti come se fossero locali, facilitando l'uso di qualsiasi tool forense standard.
* **Magnet AXIOM Cyber:** Acquisisce dati da remoto, inclusi servizi cloud (AWS, Azure).

### Considerazioni Legali
Prima di procedere, è vitale verificare:
* La giurisdizione e le leggi del paese in cui si trova il dispositivo remoto.
* L'autorizzazione legale o aziendale per accedere al sistema.
* Lo stato del dispositivo (acceso/spento).

## 5. Analisi del File System e Malware (Comando fsutil)

In indagini su malware, è spesso necessario tracciare le attività dei file, poiché il malware potrebbe rinominarsi o cancellarsi per nascondersi.

### Il Journal USN ($UsnJrnl)
NTFS mantiene un giornale delle modifiche chiamato **Update Sequence Number (USN) Journal**. Questo file traccia tutte le modifiche ai file (creazione, cancellazione, rinomina) ed è situato in una cartella nascosta (`C:\$Extend\$UsnJrnl`).

### Comando fsutil
Per analizzare questo giornale su un sistema live, si usa il comando Windows:
`fsutil usn readjournal c:`

Questo comando restituisce la cronologia delle transazioni dei file. Analizzando l'output (spesso reindirizzato su un file di testo per leggibilità), un investigatore può:
* Vedere quando un file è stato creato e chiuso.
* Identificare codici di motivo (Reason codes) come "File create", "Data extend", "Rename: old name", "Rename: new name".
* Tracciare un malware che cambia nome (es. da `Quotes.txt` a `MyQuotes.txt`) osservando gli ID dei file che rimangono costanti nonostante il cambio di nome.

Questo metodo è rapido per il triage in loco quando non si dispone di strumenti forensi avanzati come MFTECmd.
