# Modulo 6: Lavorare con i File System Microsoft e il Registro di Windows

## Introduzione ai File System
Per investigare efficacemente sulle prove digitali, è fondamentale comprendere come i sistemi operativi (OS) memorizzano e gestiscono i dati. Un file system fornisce all'OS una mappa per localizzare i dati sul disco. Sebbene esistano molti file system (come quelli per Linux e Mac), questo modulo si concentra sulle strutture Microsoft, spaziando dai sistemi legacy (DOS, Windows 9x) a quelli attuali.

### Struttura dei Dischi Rigidi
I dischi rigidi sono composti da piatti rivestiti di materiale magnetico. La geometria del disco è definita da:
* **Testine (Heads):** Leggono e scrivono i dati (due per piatto).
* **Tracce (Tracks):** Cerchi concentrici sui piatti.
* **Cilindri (Cylinders):** Colonne di tracce sovrapposte su più piatti.
* **Settori (Sectors):** Sezioni di una traccia, tipicamente di 512 byte (o 4096 byte nei dischi moderni).

I produttori utilizzano il calcolo **CHS** (Cylinder, Head, Sector) per determinare la capacità totale. Per gestire la diversa circonferenza delle tracce interne ed esterne, si utilizza la **ZBR (Zone Bit Recording)**, che raggruppa le tracce in zone per garantire una densità di dati costante.

### Partizionamento del Disco: MBR e GPT
Esistono due metodi principali per definire le partizioni su un disco:
1.  **MBR (Master Boot Record):** Situato nel settore 0. Utilizza lo schema CHS. Ha un limite di indirizzamento di 2.2 TB e supporta un massimo di 4 partizioni primarie. La tabella delle partizioni inizia all'offset esadecimale **0x1BE**.
2.  **GPT (GUID Partition Table):** Utilizza l'indirizzamento a blocchi logici (**LBA**). Supera il limite dei 2.2 TB (fino a zettabyte), supporta molte più partizioni e richiede un BIOS UEFI. È lo standard per i sistemi moderni.

## Strutture dei File Microsoft

I sistemi Microsoft organizzano i dati raggruppando i settori in **Cluster**. Un cluster è l'unità minima di allocazione per l'OS. Se un file è più piccolo di un cluster, lo spazio rimanente non viene utilizzato da altri file, creando il cosiddetto **Slack Space**.

### File System FAT (File Allocation Table)
Originariamente progettato per floppy disk, il FAT è evoluto in diverse versioni:
* **FAT12:** Per floppy disk.
* **FAT16:** Per dischi fino a 2-4 GB.
* **FAT32:** Supporta dischi più grandi e nomi di file lunghi.
* **exFAT:** Ottimizzato per memorie flash (USB, SD card) e file di grandi dimensioni.

**Caratteristiche Forensi del FAT:**
* **Cancellazione:** Quando un file viene eliminato in FAT, il sistema sostituisce il primo carattere del nome del file con il valore esadecimale **0xE5**. I dati rimangono sul disco (nello spazio non allocato) finché non vengono sovrascritti.
* **Slack Space:** Si divide in *RAM slack* (dati dalla memoria che riempiono il settore finale, comune nei vecchi OS) e *Drive slack* (spazio inutilizzato nei settori rimanenti del cluster).
* **Frammentazione:** Se i cluster non sono contigui, il file è frammentato. In FAT, le catene di cluster possono rompersi, rendendo difficile il recupero dei dati.

### File System NTFS (New Technology File System)
Introdotto con Windows NT, è il file system standard attuale. È un sistema **journaling** (registra le transazioni prima di eseguirle per stabilità).

**Master File Table (MFT):**
In NTFS, "tutto è un file". L'MFT è il cuore del sistema e contiene informazioni su ogni file e cartella (metadati). Ogni record dell'MFT è tipicamente di 1024 byte.
* **File Residenti:** Se un file è molto piccolo (circa 512 byte), il suo contenuto viene salvato direttamente all'interno del record MFT.
* **File Non Residenti:** Se il file è grande, il record MFT contiene dei puntatori (**Data Runs**) che indicano dove si trovano i dati sul disco (LCN - Logical Cluster Numbers).

**Attributi MFT Importanti:**
* **$10 ($Standard_Information):** Contiene timestamp (creazione, modifica, accesso), permessi.
* **$30 ($File_Name):** Contiene il nome del file e ulteriori timestamp.
* **$80 ($Data):** Contiene il contenuto del file (o i data runs).

**Funzionalità Avanzate NTFS:**
* **Alternate Data Streams (ADS):** Permette di nascondere dati dietro un file esistente (es. `file.txt:nascosto.txt`). Gli ADS non sono visibili nei normali editor di testo ma possono contenere malware o prove.
* **Compressione:** NTFS supporta la compressione di file, cartelle o interi volumi.
* **EFS (Encrypting File System):** Sistema di crittografia basato su chiavi pubbliche/private legato all'utente.

**Cancellazione in NTFS:**
Quando un file viene cancellato, viene spostato nel **Cestino ($Recycle.Bin)**.
* Vengono creati due file per ogni file cancellato:
    * **File $I (Metadata):** Contiene il percorso originale, la dimensione e la data di cancellazione.
    * **File $R (Data):** Contiene il contenuto effettivo del file cancellato.
* Se il Cestino viene svuotato, il record MFT viene marcato come libero, ma i dati restano recuperabili fino a sovrascrittura.

**ReFS (Resilient File System):**
Un file system più recente progettato per server e grandi volumi di dati, focalizzato sull'integrità e la disponibilità dei dati, ma non ancora utilizzabile come disco di avvio.

## Crittografia dell'Intero Disco (WDE)
La protezione dei dati sensibili (PII, segreti commerciali) ha portato all'uso diffuso della crittografia.
* **BitLocker:** Strumento Microsoft che cripta l'intero volume. Richiede un chip TPM (Trusted Platform Module) o una chiave USB/password. Per l'analisi forense, è necessario decifrare il drive (spesso tramite acquisizione live se il computer è acceso) o ottenere la chiave di ripristino.
* Esistono anche soluzioni di terze parti (VeraCrypt, Symantec, ecc.).

## Il Registro di Windows
Il Registro è un database gerarchico che memorizza configurazioni hardware, software e preferenze utente. È una miniera d'oro per le indagini.

**Struttura:**
* **Hives (Alveari):** File fisici sul disco che compongono il registro.
* **Keys (Chiavi):** Simili alle cartelle.
* **Values (Valori):** I dati effettivi.

**File del Registro e Posizione:**
* **Ntuser.dat:** Situato in `C:\Users\<NomeUtente>\`. Contiene le impostazioni specifiche dell'utente (es. file recenti, cronologia di navigazione, preferenze desktop).
* **SAM, SYSTEM, SOFTWARE, SECURITY, DEFAULT:** Situati in `C:\Windows\System32\config\`. Contengono configurazioni di sistema, account utenti locali, software installato e policy di sicurezza.

**Utilità Forense:**
Dal registro si possono estrarre: ultimi utenti loggati, dispositivi USB collegati in passato, programmi eseguiti, cronologia delle ricerche e molto altro.

## Artefatti Forensi di Windows
Oltre al file system e al registro, Windows crea file di sistema che contengono prove cruciali:

1.  **hiberfil.sys:** File di ibernazione. Contiene una copia della RAM al momento dell'ibernazione. Utile per recuperare password, documenti aperti e processi attivi.
2.  **pagefile.sys:** File di paging (memoria virtuale). Usato quando la RAM è piena. Può contenere frammenti di dati, chat o credenziali.
3.  **Prefetch (.pf):** Situati in `C:\Windows\Prefetch`. Creati per velocizzare l'avvio delle applicazioni. Per l'investigatore, mostrano quali programmi sono stati eseguiti, quante volte e l'ultima data di esecuzione. Strumenti come `PECmd.exe` servono per analizzarli.
4.  **Cronologia Internet:** I browser salvano cache, cookie, cronologia e dati di form. Questi possono rivelare le intenzioni dell'utente o l'accesso a contenuti illeciti.
5.  **$UsnJrnl:** Un giornale delle modifiche (Journal) che traccia i cambiamenti ai file sul volume NTFS. Utile per vedere la storia di creazione, modifica o rinomina dei file.
