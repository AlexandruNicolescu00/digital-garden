# Modulo 7: File System Linux e Macintosh

## Introduzione
Questo modulo esplora le strutture dei file system di Linux e macOS, fondamentali per gli investigatori forensi poiché questi sistemi operativi (OS) gestiscono e archiviano i dati in modo diverso rispetto a Windows. La comprensione di queste strutture è essenziale non solo per i computer tradizionali, ma anche per i dispositivi mobili come smartphone e tablet che derivano da queste architetture. Inoltre, il modulo copre l'utilizzo di strumenti forensi basati su Linux e comandi da riga di comando.

## 1. Strutture dei File Linux

### Storia e Panoramica
UNIX è stato creato negli anni '70 come sistema operativo multiutente e multitasking. Sebbene esistessero molte varianti certificate (come Solaris, AIX, HP-UX), oggi Linux è la variante "simil-UNIX" più diffusa. Tecnicamente, "Linux" si riferisce al kernel (il nucleo del sistema operativo mantenuto da Linus Torvalds), mentre le "distribuzioni" (come Ubuntu, Fedora, Mint, Kali) includono il kernel insieme ad altri software e interfacce grafiche.

### Struttura del File System
In Linux, "tutto è un file", inclusi dispositivi hardware come dischi rigidi e monitor. Il file system è organizzato in quattro componenti principali:

1.  **Boot Block:** Contiene il codice di bootstrap necessario per avviare il sistema. Esiste un solo boot block per il disco rigido principale.
2.  **Superblock:** Contiene metadati vitali sul file system, come la geometria del disco, lo spazio disponibile e la posizione delle tabelle degli inode. Se il superblocco si corrompe, il file system non è accessibile; per questo motivo, ne esistono copie multiple sul disco.
3.  **Inode Block:** Contiene gli "inode" (information node). Un inode è assegnato a ogni file e directory.
4.  **Data Block:** È l'area dove sono memorizzati i dati effettivi dei file e delle directory.

### Gli Inode
L'inode è un concetto cruciale in Linux. Ogni file ha un inode che contiene i suoi metadati, tra cui:
* Modalità e tipo di file.
* Proprietario (UID e GID).
* Dimensioni e timestamp (MAC times: Modifica, Accesso, Cambio di stato).
* **Importante:** L'inode *non* contiene il nome del file o il percorso (questi sono gestiti dalle directory).

**Struttura dei Puntatori degli Inode:**
Un inode ha 13 puntatori per localizzare i dati sul disco:
* **Puntatori Diretti (1-10):** Puntano direttamente ai primi 10 blocchi di dati del file.
* **Puntatore Indiretto (11):** Punta a un blocco che contiene un elenco di altri 128 puntatori ai dati.
* **Puntatore Doppio Indiretto (12):** Punta a un blocco di puntatori che a loro volta puntano ad altri blocchi di puntatori.
* **Puntatore Triplo Indiretto (13):** Aggiunge un ulteriore livello di indirizzamento per file molto grandi.

Esiste anche un "Bad Block Inode" (solitamente l'inode 1) che traccia i settori difettosi del disco. Un criminale potrebbe teoricamente marcare settori buoni come cattivi per nascondervi dati.

### Tipologie di File System Linux (ext)
* **ext2:** Il primo standard diffuso.
* **ext3:** Ha introdotto il "journaling", un meccanismo di recupero integrato che tiene traccia delle transazioni per prevenire la corruzione dei dati in caso di crash.
* **ext4:** L'attuale standard. Supporta file e volumi molto più grandi, utilizza "extents" (aree contigue di archiviazione fisica per ridurre la frammentazione) e migliora la gestione dei sottodirectory.

### Link (Collegamenti)
In Linux esistono due tipi di collegamenti ai file:
1.  **Hard Link:** Un puntatore che permette di accedere allo stesso file (stesso inode e posizione fisica) con nomi diversi. Funziona solo all'interno dello stesso file system/partizione. Se il file originale viene cancellato, i dati rimangono accessibili finché esiste almeno un hard link.
2.  **Symbolic Link (Soft Link):** È un puntatore che contiene il percorso di un altro file. Può puntare a file su altri drive o reti. Se il file di destinazione viene spostato o cancellato, il link simbolico smette di funzionare (broken link).

## 2. Strutture dei File Macintosh (macOS)

### Evoluzione
Il sistema operativo Mac è passato attraverso diverse fasi, dal "Classic" fino a macOS (basato su UNIX). I file system principali sono:
* **HFS (Hierarchical File System):** Il vecchio standard, ora obsoleto.
* **HFS+ (Mac OS Extended):** Introdotto con Mac OS 8.1, ha aumentato il numero di blocchi di allocazione, rendendo l'uso del disco più efficiente.
* **APFS (Apple File System):** Introdotto con macOS High Sierra (10.13), ottimizzato per SSD e memorie flash.

### Struttura dei File HFS/HFS+
Una caratteristica unica dei vecchi file system Mac è la struttura a "doppia forchetta" (fork) dei file:
1.  **Data Fork:** Contiene i dati effettivi creati dall'utente (es. il testo di un documento).
2.  **Resource Fork:** Contiene metadati e risorse dell'applicazione (es. icone, menu, finestre di dialogo).

### Gestione dei Volumi
In macOS, i volumi utilizzano:
* **Logical Blocks:** Unità di archiviazione di base (512 byte).
* **Allocation Blocks:** Gruppi di blocchi logici consecutivi.
* **Clumps:** Gruppi di blocchi di allocazione contigui, usati per ridurre la frammentazione.

Il sistema utilizza una struttura dati chiamata **B-tree** (albero bilanciato) per organizzare e mappare file e directory. I nodi del B-tree includono nodi Header, Index, Map e Leaf (questi ultimi contengono i dati).

### Caratteristiche di APFS
APFS è un sistema a 64-bit che offre:
* Crittografia nativa forte.
* Timestamp con precisione al nanosecondo.
* Funzionalità "Snapshot" per creare istantanee del sistema senza duplicare i dati.
* "Clonazione" dei file che non occupa spazio aggiuntivo finché il file clonato non viene modificato.

### Artefatti Forensi in macOS
* **File Plist (.plist):** File delle preferenze per applicazioni e sistema (spesso in formato binario o XML). Contengono informazioni vitali come cronologia, impostazioni di rete e utenti.
* **Keychain:** Un sistema di gestione delle password criptato che memorizza credenziali per siti web, reti Wi-Fi e applicazioni.
* **Unified Logging:** Un sistema di log complesso introdotto nelle versioni recenti.
* **FileVault:** Il sistema di crittografia del disco intero (FDE). FileVault 2 utilizza crittografia AES-128.

### Sfide nell'Acquisizione
L'acquisizione forense di Mac moderni è complessa a causa di chip di sicurezza come il **T2** e la piattaforma **Secure Enclave**. Spesso è necessario utilizzare la "macOS Recovery Mode" o strumenti specializzati (come Cellebrite Digital Collector o Sumuri Recon ITR) per bypassare le protezioni o acquisire dati decriptati, a patto di avere le credenziali dell'utente o dell'amministratore.

## 3. Strumenti Forensi Linux

L'uso di strumenti basati su Linux è vantaggioso perché sono spesso gratuiti, open-source e possono essere eseguiti da supporti avviabili (Live USB/CD) senza alterare il sistema sospetto.

### Distribuzioni Forensi
* **Kali Linux:** Una distribuzione focalizzata sui test di penetrazione e sulla sicurezza, ma che include oltre 300 strumenti forensi e di analisi. Permette di avviare il sistema in "Forensic Mode", che impedisce il montaggio automatico dei dischi per preservare le prove.
* **Paladin Edge:** Una distribuzione basata su Ubuntu fornita da Sumuri, progettata specificamente per semplificare le acquisizioni forensi.

### The Sleuth Kit (TSK) e Autopsy
* **The Sleuth Kit:** Una collezione di strumenti da riga di comando per analizzare immagini di dischi e recuperare file.
* **Autopsy:** Inizialmente era solo l'interfaccia grafica (browser-based) per Sleuth Kit. Oggi è una suite forense completa e potente (disponibile anche per Windows) che permette di analizzare file system, cercare parole chiave, estrarre metadati e generare report.

### Strumenti di Acquisizione da Riga di Comando
1.  **dd:** Il comando standard per la copia bit-stream. È potente ma basilare.
2.  **dcfldd:** Una versione potenziata di dd creata dal Dipartimento della Difesa USA, che aggiungeva l'hashing durante la copia (ora considerata obsoleta).
3.  **dc3dd:** Lo standard attuale per l'acquisizione da riga di comando. Offre funzionalità avanzate come:
    * Hashing "on-the-fly" (MD5, SHA-1, SHA-256, ecc.).
    * Barra di avanzamento.
    * Scrittura di log degli errori.
    * Verifica dei dati acquisiti.
    * Possibilità di pulire (wipe) il disco di destinazione.

### Altri Strumenti
* **Foremost:** Uno strumento per il "file carving" (recupero di file basato su header e footer) che lavora su immagini grezze. Utilizza un file di configurazione (`foremost.conf`) per identificare i tipi di file.
* **Guymager:** Un'interfaccia grafica per l'acquisizione di immagini disco in ambiente Linux, facile da usare e veloce.
