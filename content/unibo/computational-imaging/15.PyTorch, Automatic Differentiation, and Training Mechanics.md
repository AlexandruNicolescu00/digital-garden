## 🧮 Computational Representation and Differentiation

In computational imaging, PyTorch è fondamentale perché fornisce un framework concreto in cui operatori forward, architetture neurali, funzioni di loss e algoritmi di ottimizzazione possono essere scritti all'interno di un'unica struttura computazionale differenziabile.

### I Tensori come Oggetti Discreti
In PyTorch, l'oggetto base è il **tensore**. Matematicamente è un array multidimensionale, ma in pratica trasporta informazioni aggiuntive:
1. **Shape**: le dimensioni del tensore.
2. **Data type**: determina la precisione numerica.
3. **Device**: indica se il tensore risiede su CPU o GPU.
4. **Gradient tracking**: indica se le derivate rispetto a quel tensore devono essere registrate.

> ✅ **Convenzione sulle Shape**
> Un'immagine in scala di grigi di dimensione $H \times W$ non viene appiattita, ma rappresentata come un tensore di shape $(C, H, W)$ con $C=1$. In una pipeline di training, è quasi sempre incorporata nel formato standard **$(B, C, H, W)$**, dove:
> - $B$ = batch size
> - $C$ = numero di canali (per RGB $C=3$; in problemi inversi può portare significato fisico, come bobine MRI o bande spettrali).

> ⚠️ **Attenzione agli Errori di Shape**
> Un operatore che si aspetta un input di shape $(B, 1, H, W)$ e riceve $(B, H, W)$ potrebbe fallire silenziosamente o eseguire un *broadcast* non intenzionale. Ottenere le shape corrette è il primo passo per ottenere la matematica corretta.

```python
import torch
import numpy as np

# Esempio di manipolazione delle shape
x_hw = torch.tensor(array)               # (H, W)
x_chw = x_hw.unsqueeze(0)                # (C, H, W) -> (1, H, W)
x_bchw = x_chw.unsqueeze(0)              # (B, C, H, W) -> (1, 1, H, W)
```

## 📊 Data Type e Precisione Numerica

Il *data type* descrive come i numeri sono rappresentati in memoria, definendo un trade-off tra consumo di memoria e precisione algoritmica. Numericamente, un numero $a$ può essere rappresentato come una tripletta $(s, e, m)$:
$$ a = (-1)^s \cdot \sum_{i=0}^{e} m_i \cdot 2^i $$
dove $s$ è il segno, $e$ l'esponente e $m$ la mantissa.

I 4 sistemi di rappresentazione principale sono:
*   **`float64` (Double precision)**: 1 bit per il segno, 11 per l'esponente, 52 per la mantissa. È il più preciso, ma richiede 8 byte per numero. Raramente usato in AI per l'elevato costo di memoria.
 a
*   **`float32` (Single precision)**: Default per i tensori PyTorch. Richiede 4 byte per numero, mantenendo un alto livello di precisione.
*   **`float16` (Half precision)**: Richiede solo 2 byte. Estremamente efficiente ma poco preciso. Popolare per LLM, ma di scarso uso in imaging dove serve più precisione.
*   **`bfloat16`**: Variante dell'half precision che alloca meno bit all'esponente e più alla mantissa. Maggiore precisione rispetto a `float16`, ma con più probabilità di *overflow*.

## 🧱 Parameters and Modules

Una rete neurale è costruita componendo **moduli**. Ogni modulo corrisponde a una mappa parametrizzata:
*   `Linear`: implementa la trasformazione lineare $z \mapsto Wz + b$.
*   `Conv2d`: implementa una convoluzione discreta con kernel apprendibili (es. `Conv2d(1, 32, kernel_size=3)` definisce 32 filtri appresi di dimensione $3 \times 3$).
*   **Funzioni di attivazione**: implementano mappe non lineari punto per punto.
*   **Livelli di normalizzazione**: modificano le statistiche delle feature intermedie.

> ✅ **Integrazione con Operatori Fisici**
> Questa corrispondenza si estende agli operatori basati sulla fisica. Librerie come **IPPy** wrappano operatori (es. il proiettore CT o il gradiente dell'immagine) come moduli PyTorch. Una rete di ricostruzione che inizia con una backprojection basata sulla fisica, seguita da layer convoluzionali appresi, è semplicemente una composizione di moduli. I gradienti fluiscono attraverso entrambi senza distinzione.

## 🔗 Computational Graphs and Automatic Differentiation

Quando una loss scalare $L(\Theta)$ è prodotta da una sequenza di operazioni sui tensori, PyTorch registra il **computational graph** (un grafo aciclico diretto). Questo permette di calcolare $\frac{\partial L(\Theta)}{\partial \Theta}$ tramite **automatic differentiation** (backpropagation), che è l'applicazione sistematica della *chain rule*.

Per operatori basati sulla fisica il cui backward pass non è derivato automaticamente, PyTorch permette di registrare una **custom backward function**.

```python
class OperatorFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, op, x):
        """Forward pass: applica op._matvec a ogni elemento del batch"""
        ctx.op = op  # Salva l'operatore per il backward pass
        # ... logica di applicazione ...
        ctx.save_for_backward(x)
        return y

    @staticmethod
    def backward(ctx, grad_output):
        """Backward pass: applica l'operatore aggiunto (adjoint) op._adjoint"""
        op = ctx.op
        # ... logica di applicazione dell'adjoint ...
        return None, grad_input  # Nessun gradiente per `op`, solo per `x`
```

## ⚙️ Training Mechanics in Practice

### Losses e Optimizers
Una loss è un tensore scalare. Una volta calcolata, si chiama `.backward()` per ottenere i gradienti dei parametri, e un ottimizzatore aggiorna i parametri.
Per la **Vanilla SGD**, l'aggiornamento matematico è:
$$ \Theta_{k+1} = \Theta_k - \eta \nabla L(\Theta_k) $$
dove $\eta$ è il *learning rate*. **Adam** modifica questa regola ridimensionando e facendo la media dei gradienti.

```python
import torch

model = torch.nn.Linear(2, 1)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

# Esempio di un passo di ottimizzazione
prediction = model(x)
loss = torch.mean((prediction - y)**2)
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

### Learning Rate Scheduler
Impostare un learning rate fisso può portare a oscillazioni attorno al minimo. PyTorch offre scheduler per modificare $\eta$ durante il training:
1. **`ReduceLROnPlateau`**: Riduce il learning rate di una quantità predefinita quando la loss smette di diminuire.
2. **`LinearLR`**: Riduce linearmente il learning rate in un dato intervallo.
3. **`CosineAnnealingLR`**: Il più comune. Riduce gradualmente il learning rate a zero seguendo una trasformazione coseno.

## 🔄 From PyTorch to IPPy

**IPPy** estende PyTorch con componenti orientati all'imaging che si comportano come normali moduli differenziabili all'interno dello stesso computational graph.
*   `operators`: contiene modelli forward (blurring, downscaling, gradienti, proiettori CT).
*   `solvers`: contiene algoritmi classici di ricostruzione.
*   `nn`: contiene architetture neurali per problemi inversi.

Se un modello di misurazione è $y_\delta = K(x) + e$, IPPy fornisce un'implementazione dell'operatore $K$ componibile con le reti PyTorch standard.

```python
# Esempio minimale di modello di deblurring
class SmallDeblurCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(1, 16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.Conv2d(16, 16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.Conv2d(16, 1, kernel_size=3, padding=1),
            nn.Sigmoid(),
        )
    def forward(self, x):
        return self.net(x)

# Nel ciclo di training:
```

## 🔬 Why This Computational Viewpoint Matters for Imaging

I dettagli implementativi possono influenzare il modello matematico più di quanto ci si aspetti:

1. **Finite precision affects numerical stability**: L'aritmetica `float32` può accumulare errori di arrotondamento. In problemi inversi *ill-conditioned*, la differenza tra `float32` e `float64` può essere visibile nell'immagine ricostruita.
2. **Normalization changes scale and statistics**: 
   - *Batch normalization* accoppia gli elementi processati insieme, introducendo una dipendenza dalla composizione del batch.
   - *Layer normalization* opera su ogni campione indipendentemente, rendendola più adatta a setting con batch size molto piccoli (comune in imaging).
3. **Data augmentation modifies the empirical distribution**: Addestrare una rete su immagini flipped orizzontalmente le insegna implicitamente una regola di ricostruzione invariante alla riflessione. L'augmentation non è solo un trucco di regolarizzazione, ma una codifica implicita di *prior knowledge* sulla geometria del problema.

### 2. Write a minimal Linear model and verify by hand one gradient that PyTorch computes automatically.
**Risposta:**
Consideriamo il seguente modello minimale e i valori forniti nel testo:
```python
w = torch.tensor([2.0], requires_grad=True)
x = torch.tensor([3.0])
target = torch.tensor([1.0])
prediction = w * x
loss = torch.mean((prediction - target)**2)
loss.backward()
```
**Verifica a mano del gradiente:**
La funzione di loss è $L(w) = (w \cdot x - \text{target})^2$.
La derivata rispetto a $w$ (usando la chain rule) è:
$$ \frac{\partial L}{\partial w} = 2 \cdot (w \cdot x - \text{target}) \cdot x $$
Sostituendo i valori $w=2.0$, $x=3.0$, $\text{target}=1.0$:
1. $\text{prediction} = 2.0 \cdot 3.0 = 6.0$
2. $\text{loss} = (6.0 - 1.0)^2 = 25.0$
3. $\frac{\partial L}{\partial w} = 2 \cdot (6.0 - 1.0) \cdot 3.0 = 2 \cdot 5.0 \cdot 3.0 = 30.0$
Questo corrisponde esattamente all'output di PyTorch: `d loss/ d w: 30.0`.

### 3. Explain why minibatch optimization changes the numerical optimization problem even when the mathematical loss is unchanged. In particular, explain why minibatch SGD lead to a stochastic optimization procedure.
**Risposta:**
Anche se la funzione di loss matematica è la stessa, l'ottimizzazione a minibatch cambia il problema numerico perché il gradiente non viene calcolato sull'intero dataset, ma su un sottoinsieme casuale (minibatch) estratto dal `DataLoader`. Questo introduce una varianza (rumore) nella stima del gradiente ad ogni iterazione. Di conseguenza, l'aggiornamento dei parametri non segue la direzione esatta del gradiente vero (come nel full-batch), ma una sua stima rumorosa. Questo rende la procedura **stocastica** (Stochastic Gradient Descent, SGD), il che può aiutare a sfuggire dai minimi locali ma richiede un'attenta gestione del learning rate (ad esempio tramite scheduler).

### 4. Give one example where a low-level implementation choice, such as padding or dtype, changes the actual model being trained.
**Risposta:**
Il testo fornisce due esempi chiave:
1. **Data Type (`dtype`)**: Scegliere `float32` invece di `float64` cambia la stabilità numerica del modello. In problemi inversi *ill-conditioned*, l'accumulo di errori di arrotondamento in `float32` attraverso molti layer può alterare visibilmente l'immagine ricostruita rispetto a una precisione doppia.
2. **Normalization**: Scegliere tra *Batch Normalization* e *Layer Normalization* cambia il modello. La Batch Normalization accoppia i campioni all'interno dello stesso batch, introducendo una dipendenza dalla composizione del batch stesso, mentre la Layer Normalization opera indipendentemente su ogni campione, cambiando le statistiche delle rappresentazioni intermedie e il comportamento della rete, specialmente con batch size piccoli.

### 5. In the deblurring demo above, identify which part of the pipeline is the forward model, which part is the trainable inverse map, and how gradients are propagated through the full computation.
**Risposta:**
Nel demo di deblurring fornito:
*   **Forward model**: È l'operatore IPPy `K = operators.Blurring(...)`. Questo simula il processo di acquisizione applicando una sfocatura (motion blur) e aggiungendo rumore gaussiano ai dati puliti ($y_\delta = K(x) + e$).
*   **Trainable inverse map**: È la rete neurale definita come `model = SmallDeblurCNN()`. Questa rete apprende a mappare i dati misurati sfocati ($y_\delta$) verso l'immagine ricostruita ($\hat{x} = f_\Theta(y_\delta)$).
*   **Propagazione dei gradienti**: Durante il training, dopo aver calcolato la `loss` tra la `prediction` della CNN e l'immagine originale `x_batch`, si chiama `loss.backward()`. Grazie al computational graph di PyTorch, i gradienti fluiscono all'indietro attraverso i layer della `SmallDeblurCNN` (aggiornando i suoi pesi convoluzionali) e, se l'operatore forward $K$ fosse parte del graph con un adjoint registrato (come in IPPy), fluirebbe anche attraverso di esso. Nel demo specifico, $K$ è usato con `torch.no_grad()` per generare i dati, quindi i gradienti aggiornano solo i pesi della CNN per invertire l'effetto di $K$.
