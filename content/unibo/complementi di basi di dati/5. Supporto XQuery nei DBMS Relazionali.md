# Supporto XQuery nei DBMS Relazionali: DB2, Oracle e SQL Server

**Tags:** #XQuery #SQL #Database #DB2 #Oracle #SQLServer #BerkeleyDB #XML #Data_Integration
**Argomento:** Analisi comparativa dell'implementazione dello standard XQuery nei principali DBMS relazionali e nelle librerie dedicate.

---

## 1. Introduzione e Scenario
L'obiettivo di questa analisi è esaminare come lo standard **XQuery** sia stato integrato all'interno dei principali sistemi di gestione di database relazionali (DBMS). Sebbene lo standard sia unico, le implementazioni variano leggermente tra i diversi vendor.
I sistemi presi in considerazione sono:
* **IBM DB2 Express-C** (Versione 10.1)
* **Oracle XML DB** (Versione 11.2)
* **Microsoft SQL Server** (2012)
* **Oracle Berkeley DB XML** (una libreria per database XML nativi).

### Documenti di Esempio
Per illustrare le query, vengono utilizzati due documenti XML concettuali che simulano un ambiente aziendale:
1.  **Employees.xml:** Contiene i dati degli impiegati (attributi come `empno`, `deptno`, `ename`, `salary`).
2.  **Departments.xml:** Contiene i dati dei dipartimenti (attributi `deptno`, `dname`).
Il campo `deptno` funge da chiave esterna logica per collegare ("join") gli impiegati ai loro dipartimenti.

## 2. XQuery in IBM DB2

### Gestione dei Dati XML
In DB2, è possibile definire colonne di tabelle relazionali direttamente con il tipo di dato `XML`. Un prerequisito fondamentale per utilizzare questo tipo di dato è che il database utilizzi la codifica **UTF-8**.

**Inserimento Dati:**
Per inserire dati in una colonna XML, si utilizza il comando SQL `INSERT` combinato con la funzione `XMLPARSE`. Questa funzione prende in input una stringa e la converte in un frammento XML gestibile dal DBMS. È possibile specificare se preservare o meno gli spazi bianchi (*preserve whitespace*).

### Interrogazione (SQL/XML)
Le query XQuery vengono incapsulate all'interno di query SQL tramite la funzione `XMLQUERY` nella clausola `SELECT`.

**Sintassi e Clausola PASSING:**
La funzione `XMLQUERY` accetta la stringa XQuery come argomento. Un aspetto cruciale è la clausola `PASSING`: essa permette di creare un collegamento tra i dati della tabella relazionale e le variabili XQuery. Ad esempio, si può passare il contenuto della colonna `data` della tabella `departments` definendolo come variabile `$list` all'interno dell'ambiente XQuery.

**Funzionalità Supportate:**
DB2 offre un supporto molto ampio allo standard:
* **Path Expressions:** Supporto completo per tutti gli assi XPath (es. `descendant-or-self`, `child`), tipi di nodo e test.
* **Costrutti FLWOR:** Supporto completo per `for`, `let`, `where`, `order by`, `return`.
* **Aggregazione:** È possibile calcolare aggregati (come `avg`, `sum`) all'interno di clausole `let`. Ad esempio, si può calcolare lo stipendio medio di un dipartimento per ogni ciclo iterativo su un impiegato.
* **Logica Condizionale:** Supporto per il costrutto `if-then-else` per manipolare l'output in base ai valori dei dati (es. mostrare un elemento vuoto o un valore a seconda del confronto tra stipendi).
* **Operatori Insiemistici:** Supporto per operatori come `union` per combinare risultati di selezioni diverse (es. unire impiegati di un certo dipartimento con quelli che guadagnano meno di una certa cifra).
* **Quantificatori:** Utilizzo di `some ... satisfies` per verificare condizioni esistenziali su insiemi di nodi.

**Gestione dei Join:**
I join tra documenti XML (es. tra impiegati e dipartimenti) in DB2 vengono gestiti passando entrambe le tabelle nella clausola `PASSING` della funzione `XMLQUERY`. Questo rende disponibili due variabili distinte (es. `$elist` e `$dlist`) su cui è possibile iterare e applicare condizioni di join (es. `where $e/@deptno = $d/@deptno`).

## 3. XQuery in Oracle DB

### Architettura e XMLType
Oracle DB implementa il supporto a XQuery in modo molto simile a DB2, puntando sulla coesistenza tra SQL e XQuery. Introduce il tipo di dato **XMLType**, che può essere usato per colonne specifiche o per creare intere tabelle di tipo XML (`CREATE TABLE ... OF XMLType`).

**Storage (Memorizzazione):**
Oracle offre due modalità per implementare fisicamente `XMLType`:
1.  **LOB (Large Object):** Il documento è salvato come una stringa.
2.  **Structured Storage:** Il DBMS scompone automaticamente il documento in tabelle e viste relazionali basate sullo schema XML, mantenendo il modello DOM.
La scelta tra le due modalità impatta sulle performance ma è trasparente rispetto alla sintassi delle query.

### Interrogazione
Anche in Oracle si utilizza `XMLQUERY`. La sintassi è quasi identica a quella di DB2, con piccole variazioni nella clausola `PASSING` e l'aggiunta della clausola `RETURNING CONTENT`.

**Funzionalità e Limitazioni:**
Oracle supporta la maggior parte dello standard, ma con alcune eccezioni e differenze rispetto a XPath 2.0:
* Non supporta la specifica della versione di encoding nell'espressione.
* L'attributo `xml:id` genera errore.
* Il tipo `xs:duration` non è supportato (bisogna usare sottotipi specifici come `yearMonthDuration`).
* La validazione dello schema e i moduli sono opzionali/non supportati pienamente in certi contesti.
* Mancano funzioni come `fn:id`, `fn:idref` e `fn:collection` senza argomenti.

**Query Diretta su File:**
Oracle permette di interrogare direttamente file XML esterni senza caricarli in tabelle, utilizzando la funzione `doc('nomefile.xml')` all'interno di una query che seleziona dalla tabella fittizia di sistema `DUAL`.

## 4. XQuery in Microsoft SQL Server (2012)

### Livello di Supporto
SQL Server supporta un sottoinsieme delle funzionalità di XQuery, basandosi sul **Working Draft del 2004** dello standard. Questo comporta alcune limitazioni sintattiche e funzionali rispetto a DB2 e Oracle.

**Gestione Dati:**
Si utilizza il tipo di dato `XML`. Per inserire i dati, è sufficiente passare la stringa XML nel comando `INSERT` (senza funzioni di parsing esplicite come in DB2).

### Sintassi delle Query
A differenza della funzione standard `XMLQUERY`, SQL Server utilizza un metodo proprietario associato alla colonna XML: `colonna.query('espressione XQuery')`.

**Limitazioni Principali:**
* **Sequenze:** Devono essere omogenee (solo nodi o solo valori atomici). Non è supportato il costrutto `to` per i range.
* **Operatori Insiemistici:** `union`, `intersect`, `except` utilizzabili solo su sequenze di nodi.
* **Path Expressions:** Supporto limitato agli assi: `child`, `descendant`, `parent`, `attribute`, `self`, `descendant-or-self`. Tipi di nodo supportati limitati a `comment()`, `node()`, `processing-instruction()`, `text()`.

**Particolarità FLWOR:**
Le espressioni FLWOR sono supportate, ma con un comportamento peculiare nelle versioni come la 2008 R2: le espressioni assegnate a una variabile tramite `let` non vengono calcolate una sola volta, ma vengono rieseguite ogni volta che la variabile viene menzionata nella query.

**Funzioni Supportate:**
Sono comunque disponibili costrutti condizionali (`if-then-else`), operatori di confronto, operatori logici (solo `and`/`or`, manca `not` come funzione), funzioni di aggregazione e quantificatori (`some`, `every`).

## 5. Oracle Berkeley DB XML

### Natura del Sistema
A differenza dei precedenti, Oracle Berkeley DB XML non è un DBMS relazionale, ma un set di **librerie** integrabili nei linguaggi di programmazione per gestire database XML nativi. Non fornisce supporto SQL.

### Concetti Chiave
* **Container:** L'oggetto fondamentale, paragonabile a una tabella nei sistemi relazionali.
* **Storage:**
    * *By Document:* I documenti sono salvati interi come stringhe.
    * *By Node:* I documenti vengono decomposti in nodi. Questa modalità offre migliori performance e permette aggiornamenti granulari.

### Operazioni (Interfaccia Console)
Si opera tramite comandi testuali:
* `createContainer`: Crea il contenitore dati.
* `putDocument`: Inserisce un documento (da file o stringa).
* `query`: Esegue query XQuery sull'intera collezione (`collection()`) o su sottoinsiemi.

È possibile vincolare i documenti a un **XML Schema** durante la creazione del container per garantire la validità dei dati inseriti.
