# Introduzione a XML e Gestione dei Dati

**Tags:** #xml #data_management #database #web #unibo
**Argomento:** Origini, sintassi, validazione e best practices di XML.

## 1. Origini e Scopo di XML

L'**XML** (eXtensible Markup Language) deriva dall'**SGML** (Standard Generalized Markup Language).
* **Relazione con SGML:** Come SGML, permette di definire linguaggi di markup specifici per domini come finanza o matematica. Anche l'HTML è derivato dall'SGML.
* **Differenze:** L'XML è più semplice da usare rispetto a SGML ed è progettato per l'uso su Internet.
* **Utilizzo:** Nato per lo scambio di dati, qui viene analizzato per le capacità di archiviazione (storage) e ricerca (lookup).

---

## 2. Struttura di un Documento XML

Un documento XML è composto da un **Prologo** e un **Corpo** (Body).

### Il Prologo
Contiene informazioni per l'interpretazione del documento. Può includere:
1.  **Dichiarazione XML** (opzionale): Versione ed encoding (es. `<?xml version="1.0"?>`).
2.  **DOCTYPE** (opzionale): Riferimento alla grammatica per la validazione.
3.  **Istruzioni di elaborazione** (PI): Per le applicazioni software.

### Il Corpo (Body)
È costituito da un **unico elemento radice** che contiene tutti gli altri elementi annidati.

#### Sintassi degli Elementi
Gli elementi possono avere due forme:
* **Forma estesa:** `<nome attributi> contenuto </nome>`
* **Forma abbreviata** (per elementi vuoti): `<nome attributi />`

---

## 3. Regole di "Ben Formato" (Well-Formedness)

Un documento è **ben formato** se rispetta la sintassi. Errori comuni rendono il file illeggibile. Le regole principali sono:

1.  **Chiusura dei Tag:** Ogni elemento aperto deve essere chiuso o usare la forma breve. Esempio di errore: un tag aperto e mai chiuso.
2.  **Case-Sensitive:** I nomi di elementi e attributi distinguono maiuscole e minuscole (es. `<doc>` è diverso da `</DOC>`).
3.  **Annidamento Corretto:** Gli elementi non possono sovrapporsi (es. `<b><i>...</b></i>` è errato).
4.  **Unica Radice:** Deve esserci un solo elemento che racchiude tutto.
5.  **Valori degli Attributi:** Devono essere tra apici o doppi apici (es. `isbn="123"`).
6.  **Unicità degli Attributi:** Non si possono avere due attributi con lo stesso nome nello stesso elemento.

    Esempio Errato:
    ```xml
    <book author="Doe" author="Blake"/>
    ```
    Esempio Corretto:
    ```xml
    <book>
        <author>Doe</author>
        <author>Verdi</author>
    </book>
    ```

## 4. Validazione: DTD e XML Schema

Un documento è **Valido** se è ben formato, contiene una DTD e la rispetta.

### Document Type Definition (DTD)
Definisce la grammatica del documento (elementi permessi, annidamento, attributi).
Può essere interna o esterna.

```xml
Esempio di DTD interna:
    <!DOCTYPE greetings [
      <!ELEMENT greetings (#PCDATA)>
      <!ATTLIST greetings id ID #REQUIRED>
    ]>
```
### XML Schema
È un'alternativa alla DTD che permette vincoli più complessi (es. tipi di dati, chiavi, unicità) simili ai database SQL. A differenza della DTD, è scritto in sintassi XML.

## 5. Linee Guida per la Progettazione XML

Quando si usa XML per memorizzare dati, bisogna fare attenzione alla modellazione.

### 1. Dati nel contenuto, non negli attributi
I dati significativi vanno nel contenuto dell'elemento, non nell'attributo.
* *Evitare:* `<book title="Great Gatsby" />`
* *Preferire:*
    ```xml
    <book>
        <title>Great Gatsby</title>
    </book>
    ```

### 2. Metadati negli attributi
Non usare nomi generici per i tag (es. `<name>title</name>`). Usa tag specifici e metadati negli attributi.

### 3. Uso corretto delle gerarchie
Elementi correlati devono essere raggruppati sotto un genitore comune, non lasciati sequenziali allo stesso livello.
```xml
    Struttura Piatta (Da evitare):
    <db>
        <title>Libro 1</title> <author>Autore 1</author>
        <title>Libro 2</title> <author>Autore 2</author>
    </db>

    Struttura Gerarchica (Corretta):
    <db>
        <book>
            <title>Libro 1</title>
            <author>Autore 1</author>
        </book>
        <book> ... </book>
    </db>
```
