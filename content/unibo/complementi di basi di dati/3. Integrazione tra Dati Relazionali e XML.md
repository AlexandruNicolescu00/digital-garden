# Integrazione tra Dati Relazionali e XML (SQL/XML)

**Tags:** #sql #xml #database #data_integration #unibo
**Argomento:** Metodi di conversione tra modelli relazionali e XML, con focus sulle funzioni standard SQL/XML.

---

## 1. Introduzione e Scenario
Nel panorama attuale della gestione dati, esiste una dicotomia fondamentale:
1.  **Storage:** La maggior parte dei dati aziendali risiede in **Database Relazionali** (DBMS).
2.  **Scambio e Utilizzo:** Molte applicazioni utilizzano **XML** come formato standard per lo scambio, la manipolazione e la rappresentazione di dati semi-strutturati.

Quando i dati devono essere scambiati tra applicazioni diverse ma risiedono fisicamente in tabelle relazionali, è necessario un "ponte". **SQL/XML** è un'estensione standard del linguaggio SQL progettata proprio per fornire questo linguaggio comune, permettendo la conversione di dati relazionali in XML e viceversa.

---

## 2. Le Due Direzioni del Ponte
L'integrazione richiede due funzionalità principali:
* **Estrazione (SQL -> XML):** Concettualmente più semplice. Poiché XML può rappresentare sia dati strutturati che semi-strutturati, qualsiasi tabella relazionale può essere mappata in XML.
* **Storage (XML -> SQL):** Più complessa. I dati XML (gerarchici e semi-strutturati) sono difficili da adattare rigidamente al modello tabellare relazionale senza perdere flessibilità.

### Strategie di Estrazione
Esistono due approcci principali per estrarre XML da una tabella:
1.  **Mapping + XQuery:** Si crea una "vista" XML della tabella (dove il nome della tabella diventa il documento, le righe diventano elementi `<row>` e le colonne diventano elementi figli o attributi) e si interroga questa vista usando tecnologie XML come [[XQuery]].
2.  **SQL/XML:** Si utilizzano funzioni specifiche all'interno di una query SQL per trasformare i dati direttamente durante l'estrazione. Questo è il focus principale dello standard.

---

## 3. Il Linguaggio SQL/XML
SQL/XML introduce una serie di costruttori e funzioni per manipolare e generare XML direttamente dall'interno del database. La logica di esecuzione prevede prima il calcolo della tabella relazionale (come una normale `SELECT`) e successivamente la costruzione del codice XML per ogni tupla risultante.

Ecco le funzioni principali:

### XMLELEMENT
È il costruttore base. Permette di creare un singolo elemento XML specificando il nome del tag, eventuali attributi e il contenuto.
Il contenuto può essere una colonna, una stringa o la concatenazione di più valori (usando l'operatore `||`).

*Esempio logico:*
Se selezioniamo un nome da una tabella impiegati, `XMLELEMENT(NAME "emp", i.name)` produrrà:
`<emp>John</emp>`

È possibile annidare `XMLELEMENT` dentro altri `XMLELEMENT` per creare gerarchie complesse (es. un elemento `<emp>` che contiene al suo interno un elemento `<dip>`).

### XMLATTRIBUTES
Questa funzione viene utilizzata all'interno di `XMLELEMENT` per definire gli attributi del tag XML, invece che elementi figli. Se non viene specificato un nome esplicito per l'attributo, viene usato il nome della colonna di origine.

*Esempio logico:*
Generare un tag con attributo salario: `<emp sal="20000">Nome</emp>`.

### XMLFOREST
Quando si devono creare molti elementi semplici ("foglie") uno dopo l'altro, `XMLELEMENT` può risultare verboso. `XMLFOREST` (foresta di XML) permette di produrre una sequenza di elementi semplici in un colpo solo partendo da una lista di colonne.

*Esempio logico:*
Se passo nome, cognome e dipartimento a `XMLFOREST`, otterrò:
`<name>John</name><surname>Doe</surname><dep>Sales</dep>`

### XMLCONCAT
Serve a concatenare frammenti XML o elementi generati separatamente, unendoli in un unico flusso.

### XMLAGG (Aggregazione)
Questa funzione è fondamentale quando si vuole raggruppare i dati, similmente a quanto si fa con `GROUP BY` in SQL.
Mentre SQL classico aggrega valori (es. `SUM`, `COUNT`), `XMLAGG` aggrega frammenti XML. È utile per creare liste annidate.

*Esempio di utilizzo:*
Raggruppare tutti gli impiegati sotto il loro dipartimento. Si usa `GROUP BY department` e `XMLAGG` per raccogliere tutti gli elementi `<emp>` all'interno di un unico elemento padre `<department>`.

### XMLGEN
Un approccio alternativo (spesso legato a specifici vendor come Oracle, ma citato nello standard) è `XMLGEN`. Invece di usare costruttori funzionali, si utilizza un template stringa contenente variabili (es. `{$name}`), che vengono sostituite dai valori delle colonne durante l'esecuzione. Permette di usare variabili anche per i nomi dei tag, cosa non possibile con `XMLELEMENT` che richiede costanti per i nomi dei tag.

---

## 4. Stoccaggio di XML in DB Relazionali
Per quanto riguarda l'inserimento (l'operazione inversa), i sistemi utilizzano principalmente due tecniche:
1.  **Intero Documento:** L'intero XML viene salvato in un'unica colonna (es. di tipo CLOB o tipo nativo XML).
2.  **Shredding (Frammentazione):** Il documento viene "tritato" e i suoi vari pezzi vengono salvati in colonne e tabelle diverse, mappando la struttura XML sullo schema relazionale.

---

## 5. Evoluzione dello Standard
Le specifiche SQL/XML si sono evolute nel tempo sotto lo standard ISO/IEC 9075:
* **2003:** Introduzione delle funzioni base presentate sopra.
* **2006:** Aggiunta la possibilità di eseguire XQuery dentro SQL e validare documenti.
* **2008:** Aggiunte funzionalità come `TRUNCATE TABLE`.
* **2011:** Supporto per nuovi tipi di dato (es. temporali).

I principali DBMS che supportano queste funzionalità includono PostgreSQL, Oracle, IBM DB2 e MS SQL Server.
